# Local Sandbox & MicroVM Execution Guard Specification

## 1. Overview
Offline AI Studio IDE requires an autonomous **Local Sandbox & MicroVM Execution Guard** subsystem to safely evaluate code generated by autonomous agents, test untrusted scripts, and intercept destructive shell commands before they touch the host operating system.

The subsystem delivers:
1. **Isolated MicroVM Execution Engine**: Sandboxes JavaScript/TypeScript execution inside Node's `vm` context with locked globals, prototype pollution guards, and neutralized process escape vectors.
2. **Resource Quotas & Circuit Breakers**:
   - Execution Timeout: Configurable (default: 3000ms). Automatically aborts CPU-locking infinite loops (`while(true) {}`).
   - Memory Consumption Tracking: Monitors memory footprint with an allocation cap ($\le 256\text{ MB}$).
   - Stdout / Stderr Interception: Captures all `console.log`, `console.warn`, `console.error` calls and returns formatted outputs.
3. **Command Safety Policy & Heuristic Scanner**:
   - Scans shell/terminal commands and classifies them as `SAFE`, `SUSPICIOUS`, or `BLOCKED`.
   - Intercepts destructive patterns (e.g. `rm -rf /`, `rmdir /s /q C:\`, `del /f /s /q`, `dd if=`, fork bombs, raw disk writes).
4. **Interactive Sandbox Modal (`client/components/IsolatedSandboxModal.tsx`)**:
   - Live code editor, "Run in Sandbox" action, memory gauge, console output stream, and command policy inspector.
   - Global shortcut `Ctrl+Alt+S` and Header Studio button.

## 2. Data Structures & Types

### 2.1 Execution Request & Result
```typescript
export interface SandboxExecutionOptions {
  code: string;
  timeoutMs?: number; // default: 3000
  memoryLimitMb?: number; // default: 256
  envVars?: Record<string, string>;
  allowNetwork?: boolean; // default: false
}

export interface SandboxExecutionResult {
  success: boolean;
  returnValue: any;
  logs: Array<{ type: 'log' | 'warn' | 'error'; message: string; timestamp: string }>;
  executionTimeMs: number;
  memoryDeltaMb: number;
  timedOut: boolean;
  error?: string;
  securityViolations: string[];
}
```

### 2.2 Command Inspection Result
```typescript
export interface CommandInspectionResult {
  command: string;
  status: 'SAFE' | 'SUSPICIOUS' | 'BLOCKED';
  riskScore: number; // 0 (completely safe) - 100 (extreme danger)
  reasons: string[];
  suggestedAlternative?: string;
  category: 'file_system' | 'network' | 'process' | 'system' | 'harmless';
}
```

## 3. Architecture & Interfaces

### 3.1 `lib/sandbox/isolatedExecutionGuard.ts`
- **`runInSandbox(options: SandboxExecutionOptions): Promise<SandboxExecutionResult>`**:
  Runs code in an isolated `vm.createContext()` with sealed prototype objects (`Object.freeze`), intercepted `console`, and a strict `timeout` timer.
- **`inspectCommand(command: string): CommandInspectionResult`**:
  Performs regex and token analysis on shell commands to detect destructive patterns, unauthorized file deletions, or system alteration calls.
- **`getSandboxStatus(): object`**:
  Returns current system memory, active sandboxes count, and execution history.

### 3.2 API Endpoints
- `POST /api/sandbox/execute`: Executes code inside the isolated MicroVM.
- `POST /api/sandbox/inspect-command`: Analyzes a shell command against safety policies.
- `GET /api/sandbox/status`: Returns current sandbox telemetry and quotas.

### 3.3 UI: `client/components/IsolatedSandboxModal.tsx`
- Interactive runner with code editor, execution results, latency gauge, memory usage meter, and safety inspection tab.
- Integrated into `components/Playground.tsx` with hotkey `Ctrl+Alt+S`.

## 4. Testing & Verification Criteria
1. `scripts/test-sandbox-engine.js`:
   - Asserts code execution returns expected values and console logs.
   - Asserts infinite loop (`while(true){}`) is killed within 3000ms with `timedOut: true`.
   - Asserts prototype pollution (`Object.prototype.polluted = true`) does not leak into host process.
   - Asserts destructive commands (`rm -rf /`, `del /f /s /q C:\*`, fork bomb) are flagged as `BLOCKED` with risk score 100.
2. `scripts/test-sandbox-routes.js`:
   - Verifies HTTP 200 responses across all `/api/sandbox/*` routes.
3. UI build check verifies clean Next.js compilation.
